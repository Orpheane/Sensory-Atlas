# Sensory Atlas - proposed roadmap

This document is a forward-looking plan, not a claim that the functionality already exists.

## Phase 0 - Initial concept (current)
- Define the problem from lived experience.
- Develop a solution hypothesis and core user needs.
- Establish design values around individuality, trust, and privacy.
- Publish a concept website and fictional interactive example.

## Phase 1 - Listen and validate
- Interview or survey willing participants with different sensory preferences.
- Check whether noise, lighting, crowds, and retreat options are the right initial categories.
- Explore whether ratings should describe observed intensity rather than personal comfort.
- Test low-fidelity prototypes and compare existing solutions.

## Phase 2 - Plan the MVP
- Confirm the technical stack and hosting constraints.
- Design venues, observations, timestamps, uncertainty, and moderation workflows.
- Support account-free browsing and optional on-device preferences.
- Set confidence indicators for community observations.
- Define testable accessibility and privacy requirements.

## Phase 3 - Working MVP
- Implement map and text-first list views.
- Add place details and preference-based filtering.
- Pilot community feedback, moderation, corrections, and stale-data indicators.
- Explain recommendations and data provenance transparently.
- Perform accessibility and usability testing with participants.

## Phase 4 - Local pilot
- Start with a manageable number of actual places and contributors.
- Evaluate usefulness, comprehension, trust, and barriers to participation.
- Improve before considering expansion.

## Future considerations
- Time-of-day trends only where enough reliable data exists.
- Opt-in environmental measurements with limitations clearly described.
- Partnerships with public institutions and organizations.
- More languages and regional accessibility research.

## What will not be assumed
- Reports are not objective proof of safety or comfort.
- Previous observations cannot guarantee present conditions.
- A diagnosis is not required to browse a sensory map.
- A visual map must never be the only way to access content.
